# 추후 작업

지금은 9주차 테스트 단계라 하지 않는다. 판정이 **개발 착수(본인 첨부율 60% 이상)**로 나오면 아래 순서로 진행한다.
기록일: 2026-10-08

## 테스트 기간에 챙길 것

- [ ] Supabase 무료 프로젝트는 1주일 동안 접속이 없으면 일시 중지된다. 테스트 기간에는 매일 쓰므로 괜찮지만, 방학 등 쉬는 기간 전에는 확인한다.
- [ ] Preview 배포도 운영 DB를 같이 쓴다. Preview에서는 화면만 보고 가입·팀 만들기·올리기는 하지 않는다.

## 1. 요금제와 환경 분리

- [ ] Supabase Pro($25/월): 일시 중지 없음, 매일 백업
- [ ] 개발용 Supabase 프로젝트를 따로 두고 Vercel Preview 환경 변수를 그쪽으로 연결 (Pro면 브랜치 기능도 가능)
- [ ] Vercel Pro($20/월·인): Hobby는 비상업용이라 유료화·광고를 붙이면 필요

## 2. 실제 서비스에 빠져 있는 기능

- [ ] 비밀번호 재설정: 메일 발송 서비스(Resend 등 SMTP) 연결 → 재설정 메일. 연결 후 이메일 인증도 다시 켤지 결정 (`supabase/config.toml`의 `enable_confirmations`)
- [ ] 회원 탈퇴와 데이터 삭제, 올린 파일 보관 기간
- [ ] 개인정보처리방침·이용약관 (이메일을 받으므로 필요)
- [ ] 카카오 로그인 켜기 (코드 준비됨 → README “소셜 로그인 붙이기”)
- [ ] 운영자 인증: 공유 비밀번호(`ADMIN_PASSWORD`) → Supabase Auth의 관리자 역할
- [ ] 남용 방지: 가입·업로드·초대 코드 입력 횟수 제한
- [ ] 한 기기에서 여러 계정을 쓸 때 알림 기기 정리 (지금은 마지막으로 알림을 켠 계정에 붙음)

## 3. 앱·모바일 확장

1. [ ] PWA로 먼저 확인 (홈 화면 아이콘·웹 푸시는 이미 있음)
2. [ ] 네이티브 앱이 필요하면 Expo(React Native)로, 같은 Supabase 계정·DB 사용
   - [ ] 서버 액션 안의 로직(팀 참여·업로드·판정)을 웹·앱이 같이 부를 API(Route Handler 또는 Supabase RPC)로 분리
   - [ ] 앱이 DB를 직접 읽으면 `members.user_id = auth.uid()` 기준 RLS 정책 추가 (지금은 RLS 켜고 정책 없음, 서버만 접근)
   - [ ] 알림: 웹 푸시와 함께 Expo Push(FCM/APNs), `notifications` 테이블 그대로 사용

## 4. 운영

- [ ] 자체 도메인 연결 → Vercel `APP_URL`, Supabase Vault `boim_cron_url`, Auth의 사이트 주소·Redirect URLs 함께 변경
- [ ] 오류 감시: Sentry
- [ ] 사용 분석: PostHog (가입 이탈 등 퍼널)
- [ ] 정식 시작 때 비밀 값 새로 발급: DB 비밀번호, 서비스 키, VAPID 키, `CRON_SECRET`, 운영 비밀번호

## 5. 플랫폼을 바꿀 신호 (그 전까지는 Vercel + Supabase 유지)

- Vercel 함수 비용이 서버 한 대 값보다 커질 때
- 긴 작업(AI 검수, 대용량 파일 처리)이 Vercel 실행 시간 제한에 걸릴 때
- 기관 납품 등으로 국내 클라우드 같은 데이터 위치 요건이 생길 때

바꿀 때도 전부 옮기지 않고 필요한 부분만 뗀다. 예: AI 검수만 별도 서버(Fly.io·Render), 계정·DB는 Supabase 유지.
